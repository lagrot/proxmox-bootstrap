HOMELAB UPDATE QUICK GUIDE
==========================

Read over SSH:
  cd /root/proxmox-bootstrap
  less UPDATE-QUICK-GUIDE.txt

Words in ALL_CAPS are placeholders. Replace them with a real value.

NORMAL USE
----------
CT 200, 210, and 220 install Debian security updates automatically.
The recovery backup is reported for visibility; it does not gate those updates.

Run the one normal check:
  bash scripts/step20-status.sh

If all three CTs say ENABLED and no failed last run is shown, do nothing.

MANUAL UPDATES
--------------
Do not use a generic apt or Docker command to update applications.
Home Assistant: Settings -> System -> Updates in its web interface.
Frigate:        follow docs/step18-frigate-upgrade.md.
Proxmox, Docker, MQTT feature releases, Hermes, and Zigbee firmware do not yet
have one generic apply procedure. Ask the project owner and review the relevant
release notes and recovery plan before changing them.

SNAPSHOTS
---------
Snapshots are temporary rollback points, not backups.
List:
  pct listsnapshot 200
  pct listsnapshot 210
  pct listsnapshot 220
Delete only after the guest is healthy and the exact name is confirmed:
  pct delsnapshot CTID SNAPSHOT_NAME
Snapshot deletion cannot be undone. Never guess an ID or name.

TROUBLESHOOTING
---------------
Validate automatic-update configuration:
  bash scripts/step20g-unattended-upgrades-validation.sh
Inspect one CT's update log (replace CTID):
  pct exec CTID -- journalctl -u apt-daily-upgrade.service --since "7 days ago" --no-pager
Service checks:
  MQTT:    bash scripts/step05d-mqtt-auth-validation.sh
  Frigate: bash scripts/step10f-frigate-mqtt-validation.sh
  Hermes:  bash scripts/step20c-post-update-validation.sh hermes
If unsure, stop. Do not reboot Proxmox, delete a snapshot, or run an upgrade.
Read docs/step20-update-operations.md or contact the project owner.
